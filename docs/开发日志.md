## 一、项目概述

- **产品**：ClassBoard 班级课表平台（自托管，适配电脑与手机浏览器）
- **定位**：**班级课表发布平台**（2026-10-14 会话 88–93 改造完成）——班级负责人（班长/学委）维护一份权威课表 + 学期日历 + 单课调整，公开面免登录只看；支持班级共管、通知、作业/考试公示、变更记录与回退、导入导出 v6。课程数据以 PDF 导入为主（正方教务系统导出 PDF，前端解析）、手动录入为辅
- **技术栈**：后端 Node.js + Express + better-sqlite3（SQLite WAL）；前端 Vue 3 + Vite + Pinia；单容器 Docker 部署，前端构建产物由后端静态托管，同源 `/api`
- **文档**：`docs/01-PRD`、`02-技术设计`、`03-设计语言`、`04-UI设计`、`05-UI组件参考.html`

### 会话 80 · 课程数据模型重构：逐格子存储 + 丢课修复（2026-10-09，ZCode 会话）

- **用户反馈**：完成课程添加后，「更新项目」相关功能会丢失课程，尤其实验课；课程表数据存储格式可能有问题；希望改为「每门课一组、组下逐个记录每个上课时间，节次与周次逐项展开、不分段不简写，读取时再由程序处理，元数据不改」
- **排查结论（旧实现的丢课路径）**：
  1. **覆盖导入**清空整学期课程（`DELETE FROM course WHERE semester_id=?`），而 PDF 解析永远只产理论课（`utils/pdf.ts` 写死 `type='course'`）→ 先手动录入的实验课必然被清空
  2. **模板去重键不含课程类型**（`name|weekday|startPeriod-endPeriod`）→ 同名同时间的实验课被误判"已存在"而静默跳过，界面仍提示导入成功
  3. **JSON 恢复三处缺陷**：`DELETE` 无 `user_id` 过滤（清空全库所有用户数据）、接口无 admin 限制、校验不通过的行静默 `continue` 丢弃而返回计数用原始数组长度（"恢复完成 25 门"可能实际只写入 11 门）
  4. **前端显示层**：`loadCourses` 有 `if (list.length)` 守卫导致真实清空后内存仍留旧数据；任何请求失败即回退内置 mock 课表 → 真实课程"看起来消失"
  5. **拖拽调课**旧实现把一门课拆成多条散行（缩小原行周次 + 新增一行），课程组被拆散
- **新数据模型（三层，节次/周次一律逐项展开）**：
